# main 번역기 수정 계획

대상은 `main`의 `ba1ec092`이다. 이 문서는 구현 계획이며, 아래 변경의 의미 보존을 이미 증명했다는 뜻은 아니다.

## 반드시 지킬 기준

- 번역기는 실제 SpecTec IL AST를 재귀적으로 Maude에 옮기는, 논문에 정의와 함께 제출할 수 있을 만큼 간결하고 검토 가능한 OCaml 코드여야 한다. 원본 생성자와 해당 변환을 가까이 두고, 예제별 예외나 숨은 두 번째 변환 파이프라인을 만들지 않는다.
- **하드코딩 기준:** 번역기가 원본 선언·규칙·명시적 hint에 없는 Wasm의 모양을 미리 전제하고, 어떤 부분이 값·명령어·상태·focus인지 등의 역할이나 변환 전략을 추론해서는 안 된다. Wasm 이름의 직접 비교뿐 아니라 `val* instr* instr_1*`처럼 특정 배치를 암묵적으로 가정하는 코드도 해당한다. IL 생성자를 읽거나 원본 규칙의 변수 의존성을 분석하는 것 자체는 하드코딩의 증거가 아니다. 다만 그 분석으로 선택한 전략이 임의의 지원 대상에서 정당한지는 별도로 검증한다.
- 지원하지 못하는 원본 형태는 이유와 위치를 포함해 진단한다. Wasm 예제의 결과가 같다는 것만으로 수학적 정확성을 주장하지 않는다.

## 개발 순서

1. **수정 전 재점검.** main 전체 변환 경로에서 역할과 전략을 결정하는 분기를 다시 열거하고, 각 결정의 근거가 IL 의미·원본 선언·명시적 hint 중 어디에 있는지 기록한다. 근거 없는 Wasm 형태 가정이 발견되면 수정 범위에 추가한다. 확인된 번역 오류와 지원 제한은 하드코딩과 구분한다.

2. **focus 조건 선택을 hint로 명시.** 새 rule annotation의 계약을 먼저 정한다. annotation이 붙은 원본 규칙에서 생성하는 `identifyFocus`, `identifyFocusPure`, `identifyFocusRead`에는 현재처럼 그 규칙의 원본 조건을 생성한다. annotation이 없는 규칙의 helper는 입력 패턴의 모양만 검사하고 원본 조건을 복사하지 않는다. 실제 실행 규칙의 조건은 유지한다. annotation의 유효 위치와 조건을 Maude helper로 옮길 수 없는 경우의 진단을 정의한다. 현재 Wasm에서 조건이 필요한 것으로 확인한 규칙에 annotation을 붙이되, 번역기에는 그 규칙 이름이나 개수 `9`를 넣지 않는다. 조건을 생략한 helper가 실행 가능한 focus를 놓치거나 원본에 없는 결과를 만들지 않는지도 별도로 확인한다.

3. **함수 clause 우선순위 오류 수정.** membership choice와 `hint(maude_rule)` 경로도 원본 `DefD` clause를 앞에서부터 선택하는 의미를 보존하게 한다. 뒤 clause에는 앞 clause가 적용되지 않는 입력이라는 조건이 필요하다. 일반 함수 경로의 겹침·제외 처리를 공통으로 활용하되, 앞 clause의 적용 여부를 안전하게 표현할 수 없으면 조용히 겹치는 규칙을 내지 말고 진단한다. 비Wasm 예제 `pick(0)=0; pick(n)=1`에서 `pick(0)`의 결과가 `0`뿐인지, membership choice에서도 앞 clause가 우선하는지 확인한다.

4. **`ListN` identity 반복 오류 수정.** `x^n{x <- xs}`를 `xs`로 바로 치환하는 경로에서 `n`과 `xs`의 길이 관계가 사라지지 않게 한다. `ListN` shortcut을 제한하고, 일반 helper로 보내는 경우에도 원본 IL의 길이 불일치 동작(`ITER-SUP-bad`의 `eps`)을 보존하는지 확인한다. valid IL의 `n=0, xs=[7]` 반례와 길이가 맞는 경우를 모두 검사한다. 이 반례는 현재 `.spectec` frontend가 직접 받아들인 예제라는 뜻은 아니다.

수정 후에는 동일 입력의 기존·변경 생성 Maude를 비교하고, 번역·Maude load·위 비Wasm 반례·관련 Wasm 실행을 확인한다. 일반적인 의미 보존 주장은 이 검사 결과와 구별한다.
